# SenseNav Route Scoring API — Frontend Integration Guide

This document is for teammates building the Flutter frontend. It explains
what the API does, how to call it, and what to expect back.

---

## What this API does

You give it a starting point and a destination. It calls Google Directions
to get 2-3 possible walking routes, then scores each route by how busy the
nearby streets currently are (using City of Melbourne's live pedestrian
sensor data), and returns each route with a sensitivity label (Low /
Medium / High) and a color to render it with.


## Endpoints

### `GET /`
Just a health check — confirms the server is alive.

**Response:**
```json
{ "status": "SenseNav API is running" }
```

### `POST /route`
The main endpoint. Send an origin and destination, get back scored routes.

**Request body:**
```json
{
  "origin": { "lat": -37.8136, "lng": 144.9631 },
  "destination": { "lat": -37.8226, "lng": 144.9548 }
}
```

`lat`/`lng` are just standard latitude/longitude as decimal numbers.
`origin` should come from either the device's current GPS location, or
wherever the user typed/selected in the "From" field. `destination`
comes from the Places Autocomplete search.

**Response body:**
```json
{
  "mode": "scored",
  "routes": [
    {
      "summary": "Elizabeth St and Flinders St",
      "polyline": "bnxeF}axsZfBm@N@DEHOh@Of@S...",
      "distance_text": "1.8 km",
      "duration_text": "26 mins",
      "sensitivity": "Medium",
      "color": "#EF9F27",
      "avg_pedestrian_count": 37.39
    },
    {
      "summary": "Collins St",
      "polyline": "bnxeF}axsZfBm@N@DEHOh@Of@S...",
      "distance_text": "1.7 km",
      "duration_text": "26 mins",
      "sensitivity": "Low",
      "color": "#3B8BD4",
      "avg_pedestrian_count": 27.05
    }
  ]
}
```

---

## Understanding the response fields

- **`mode`** — either `"scored"` or `"unscored"`. Check this first.
  - `"scored"`: at least one route has real sensor data. Show the
    multi-route colored view.
  - `"unscored"`: no sensor coverage anywhere for this trip (this happens
    for areas outside inner Melbourne CBD, since that's where the
    sensors are). Only **one route** will be returned in this case, with
    `sensitivity` and `color` both `null`. Just show it as a plain route,
    like normal Google Maps — no color legend, no sensitivity claim.

- **`polyline`** — an encoded path string (Google's standard polyline
  format). Most map SDKs, including Google Maps Flutter, have a built-in
  decoder for this — you don't need to parse it by hand. Draw it as a
  line on the map.

- **`distance_text`** / **`duration_text`** — human-readable strings,
  ready to display as-is (e.g. "1.8 km", "26 mins").

- **`sensitivity`** — `"Low"`, `"Medium"`, `"High"`, or `null` (if that
  specific route had no nearby sensor data, even in `"scored"` mode).

- **`color`** — a hex color string matching the sensitivity
  (`#3B8BD4` blue = Low, `#EF9F27` amber = Medium, `#E24B4A` red = High),
  or `null`. Use this directly as the polyline's stroke color — no need
  to map sensitivity to a color yourselves, it's already done for you.

- **`avg_pedestrian_count`** — the raw number behind the sensitivity
  label, in case you want to show it somewhere (e.g. "~37 people/min
  nearby"). Can be `null` if unscored.

## Calling it from Flutter

Using the `http` package:

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

Future<Map<String, dynamic>> getScoredRoutes({
  required double originLat,
  required double originLng,
  required double destLat,
  required double destLng,
}) async {
  final url = Uri.parse('http://34.172.95.142:8000/route');

  final response = await http.post(
    url,
    headers: {'Content-Type': 'application/json'},
    body: jsonEncode({
      'origin': {'lat': originLat, 'lng': originLng},
      'destination': {'lat': destLat, 'lng': destLng},
    }),
  );

  if (response.statusCode == 200) {
    return jsonDecode(response.body);
  } else {
    throw Exception('Route request failed: ${response.statusCode}');
  }
}
```

Then check `result['mode']` to decide how to render, and loop through
`result['routes']` to draw each polyline with its given `color`.

## A note on data freshness

The sensor data behind this API only refreshes while an ingestion script
is actively running on the VM. If route scores seem stale or every route
comes back `"unscored"` unexpectedly, check with Elijah whether the
ingestion script is currently running.
